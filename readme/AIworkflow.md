## 📌 版本命名與推進規則（極度重要）

本專案使用自訂版本號 `v X.Y.Z`，雙軌並行：底層版本與全域版本各自演進。
`beta-n` 後綴**僅用於除錯**，不是所有更新的容器。

### 底層版本（X=0）

- **`X = 0`**：底層功能開發。
- **`Y`**：較大的功能更新（如 Google Drive 備份、IndexedDB 重構、多幣別記帳、全站 i18n）。大功能推進時 `Y` 遞增、`Z` 歸零。
- **`Z`**：該大功能底下正在推進的子功能更新。
- **`beta-n`**：僅在「已定版的底層版本需要修 bug」時出現，`a→b→c` 推進；修完即收斂，移除 `beta` 後綴回歸正式版。

### 全域版本（X=1）

- **`X = 1`**：UI/UX 介面更新。
- **`Y`**：`0`=全域、`1`=電腦端、`2`=手機端、`3`=平板端。
- **`Z`**：該模組的小功能更新次數。
- **`beta-n`**：僅用於除錯，修完收斂。

### 兩軌互動（核心修正）

- 底層與全域**各自以正式數字推進**，互不充當對方的容器。
- 底層的大功能/子功能推進，直接動底層 `Y`/`Z`，**不產生 beta**。
- **廢除「底層迭代對全域只是 beta」的舊說法**。全域只在自己 UI/UX 有變動時動全域 `Z`；底層成果以「全域對應版本」體現。
- `beta` 只在修 bug 時出現，不會因功能推進而氾濫。

### 判定流程

```
需求進來
├─ 底層（資料/邏輯/儲存/API）
│  ├─ 大功能 → Y 遞增，Z 歸零（正式版，無 beta）
│  ├─ 子功能 → Z 遞增（正式版，無 beta）
│  └─ 除錯 → 當前底層版本加 beta-n，修完移除 beta
└─ 全域（UI/UX）
   ├─ 小功能 → 全域 Z 遞增（正式版）
   └─ 除錯 → 全域版本加 beta-n，修完移除 beta
```

### Service Worker 快取

`sw.js` 的 `CACHE_NAME` 對應**全域正式版**（如 `my-space-cache-v1.0.8`）；除錯期間可加後綴（如 `-beta-a`）。
