## 📌 版本命名與推進規則（極度重要）

本專案使用自訂版本號 `v X.Y.Z`。
底層版本與全域版本雙軌並行。
`beta-n` 後綴**僅用於除錯**，不是所有更新的容器。

### 底層版本（X=0）

- **`X = 0`**：代表底層功能開發。
- **`Y`**：代表較大的功能更新。
- **`Y` 範例**：如 Google Drive 備份。
- **`Y` 範例**：如 IndexedDB 重構。
- **`Y` 範例**：如多幣別記帳。
- **`Y` 範例**：如全站 i18n。
- **`Y` 規則**：大功能推進時 `Y` 遞增，`Z` 歸零。
- **`Z`**：代表該大功能底下正在推進的子功能更新。
- **`beta-n`**：僅在「已定版的底層版本需要修 bug」時出現。
- **`beta-n` 規則**：`a` → `b` → `c` 依序推進。
- **`beta-n` 規則**：修完即收斂，移除 `beta` 後綴回歸正式版。

### 全域版本（X=1）

- **`X = 1`**：代表 UI/UX 介面更新。
- **`Y`**：代表適用裝置。
- **`Y=0`**：代表全域版本。
- **`Y=1`**：代表電腦端。
- **`Y=2`**：代表手機端。
- **`Y=3`**：代表平板端。
- **`Z`**：代表該模組的小功能更新次數。
- **`beta-n`**：僅用於除錯，修完收斂。

### 兩軌互動（核心修正）

- 底層與全域**各自以正式數字推進**。
- 底層與全域**互不充當對方的容器**。
- 底層的大功能/子功能推進，直接動底層 `Y`/`Z`。
- 底層的大功能/子功能推進，**不產生 beta**。
- **廢除**「底層迭代對全域只是 beta」的舊說法。
- 全域只在自己 UI/UX 有變動時動全域 `Z`。
- 底層成果以「全域對應版本」體現。
- `beta` 只在修 bug 時出現。
- `beta` 不會因功能推進而氾濫。

### 判定流程

需求進來
├─ 底層（資料/邏輯/儲存/API）
│  ├─ 大功能 → Y 遞增，Z 歸零（正式版，無 beta）
│  ├─ 子功能 → Z 遞增（正式版，無 beta）
│  └─ 除錯 → 當前底層版本加 beta-n，修完移除 beta
└─ 全域（UI/UX）
   ├─ 小功能 → 全域 Z 遞增（正式版）
   └─ 除錯 → 全域版本加 beta-n，修完移除 beta

### Service Worker 快取

- `sw.js` 的 `CACHE_NAME` 對應**全域正式版**。
- 例如：`my-space-cache-v1.0.8`。
- 除錯期間可加後綴。
- 例如：`my-space-cache-v1.0.8-beta-a`。

### 當前版本狀態（校正後）

- **底層版本**：`v0.6.0-beta-b`。
- **全域版本**：`v1.0.8-beta-b`。
- **SW 快取**：`my-space-cache-v1.0.8-beta-b`。
- **除錯進度 a**：`v0.6.0-beta-a`（法務連結、Token 持久化、i18n 缺 key）。
- **除錯進度 b**：`v0.6.0-beta-b`（Token 過期處理、401 攔截、全面 i18n 補齊、文件一致性）。

## ⚙️ 程式碼撰寫規範

1. **模組化封裝**：所有事件監聽必須包在 `(function() { ... })();` 中。
2. **防重複綁定**：使用 `dataset.bound` 防止重複綁定。
3. **自訂彈窗**：禁止使用原生的 `alert()`。
4. **自訂彈窗**：禁止使用原生的 `confirm()`。
5. **自訂彈窗**：禁止使用原生的 `prompt()`。
6. **自訂彈窗**：所有確認動作請使用 `customConfirm(title, msg, okText, cancelText, isDanger)` 這個 Promise 函式。
7. **Toast 提示**：使用 `toast('訊息')` 顯示操作回饋。
8. **DOM 查詢**：使用 `const $ = (s) => document.querySelector(s)`。
9. **DOM 查詢**：使用 `const $$ = (s) => document.querySelectorAll(s)`。
10. **資料儲存**：使用封裝好的 `LS` 物件（`LS.get`、`LS.set`）。
11. **圖片音效**：圖片與音效用 `IDB`（IndexedDB）。
12. **日期處理**：使用 `todayKey()` 取得 `YYYY-MM-DD`。
13. **日期處理**：使用 `dateKey(d)` 轉換 Date 物件。
14. **Google API**：使用 Google Identity Services (GIS) 進行登入。
15. **Google API**：將 Token 暫存於 LocalStorage (key: `googleToken`)。
16. **Google API**：將到期時間存於 LocalStorage (key: `googleTokenExp`)。
17. **多語系 (i18n)**：禁止在 HTML 中寫死任何介面文字。
18. **多語系 (i18n)**：所有文字必須加上 `data-i18n="key"`。
19. **多語系 (i18n)**：所有 placeholder 必須加上 `data-i18n-placeholder="key"`。
20. **多語系 (i18n)**：在 `lang.js` 中集中管理所有 `zh-TW` 與 `en` 的翻譯字串。
21. **多語系 (i18n)**：`script.js` 中的 `applyLanguage(lang)` 負責替換所有 `data-i18n` 元素。
22. **多語系 (i18n)**：`applyLanguage` **必須重新呼叫所有渲染函式**。
23. **多語系 (i18n)**：程式碼中使用的每個 i18n key，**必須**在 `lang.js` 兩邊都存在，避免 fallback。

當我提出需求時，請依照以下步驟回覆：

1. **版本判定**：依上方「判定流程」告訴我這次更新屬於哪個級別。
2. **版本判定**：列出**底層與全域的舊 → 新版本對照**。
3. **版本判定**：列出 `sw.js` 的 `CACHE_NAME` 新值。
4. **程式碼提供**：若改動較小，請用「🔍 找到這段程式碼… ✅ 替換為…」的方式。
5. **程式碼提供**：若改動較大、涉及架構或 HTML 結構，請直接提供**整份檔案的完整程式碼**。
6. **程式碼提供**：用註解標示 `// [NEW]` 方便我對照。
7. **排版規範（極度重要）**：為了避免複製不全，**所有提供的程式碼（包含 HTML, CSS, JS）請遵守「一個元素/屬性一行」的原則**。
   - HTML 標籤屬性請換行。
   - CSS 每個屬性請換行。
   - JS 請避免過長的單行程式碼，必要時拆分成多行。
8. **文檔同步**：若有必要，請一併提供 `changelog.md` 或 `README.md` 的更新段落。
9. **測試清單**：列出 3–5 點我需要手動測試的項目與預期結果。
