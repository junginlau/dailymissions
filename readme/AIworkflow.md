## 🎯 核心專案資訊

- **技術棧**：原生 HTML、Vanilla CSS、原生 JavaScript (ES6+)。
- **框架依賴**：無任何外部框架依賴。
- **設計風格**：Glassmorphism（毛玻璃）、深淺色主題自動適應、極簡無邊框。
- **佈局核心**：**外層絕對不滾動（`html, body, .app` 鎖死 `overflow: hidden`），所有內容都在內部的 `.scroll-box` 或獨立區塊內滾動。Footer 永遠固定於底部。**
- **資料儲存**：所有資料存在瀏覽器端（LocalStorage、IndexedDB、Cookie），不上傳伺服器。
- **備份機制**：支援手動匯出 JSON、Google Drive 雲端備份。
- **主要檔案**：`index.html`、`style.css`、`script.js`、`sw.js`、`manifest.json`、`lang.js`、法務檔案（`privacy.html`、`terms.html`、`about.html`）。

## 📌 版本命名與推進規則（極度重要）

本專案使用自訂版本號 `v X.Y.Z`。
底層版本與全域版本雙軌並行。
`beta-n` 後綴**僅用於除錯**，不是所有更新的容器。

### 底層版本（X=0）
- **`X = 0`**：代表底層功能開發。
- **`Y`**：代表較大的功能更新（如 Google Drive 備份、IndexedDB 重構、多幣別記帳、全站 i18n）。大功能推進時 `Y` 遞增，`Z` 歸零。
- **`Z`**：代表該大功能底下正在推進的子功能更新。
- **`beta-n`**：僅在「已定版的底層版本需要修 bug」時出現，`a` → `b` → `c` 依序推進。修完即收斂，移除 `beta` 後綴回歸正式版。

### 全域版本（X=1）
- **`X = 1`**：代表 UI/UX 介面更新。
- **`Y`**：代表適用裝置。`0`=全域、`1`=電腦端、`2`=手機端、`3`=平板端。
- **`Z`**：代表該模組的小功能更新次數。
- **`beta-n`**：僅用於除錯，修完收斂。

### 兩軌互動（核心修正）
- 底層與全域**各自以正式數字推進**，互不充當對方的容器。
- 大功能/子功能推進，直接動底層 `Y`/`Z`，**不產生 beta**。
- 全域只在自己 UI/UX 有變動時動全域 `Z`。
- `beta` 只在修 bug 時出現，不會因功能推進而氾濫。

### 判定流程
需求進來
├─ 底層（資料/邏輯/儲存/API）
│  ├─ 大功能 → Y 遞增，Z 歸零（正式版，無 beta）
│  ├─ 子功能 → Z 遞增（正式版，無 beta）
│  └─ 除錯 → 當前底層版本加 beta-n，修完移除 beta
└─ 全域（UI/UX）
   ├─ 小功能 → 全域 Z 遞增（正式版）
   └─ 除錯 → 全域版本加 beta-n，修完移除 beta

### Service Worker 快取
- `sw.js` 的 `CACHE_NAME` 對應**全域正式版**（如 `my-space-cache-v1.0.9`）。
- 除錯期間可加後綴（如 `my-space-cache-v1.0.9-beta-b15`）。

### 當前版本狀態（2026-11-16 更新）
- **底層版本**：`v0.6.1`（正式版，i18n 已收斂）。
- **全域版本**：`v1.0.9`（正式版，修復所有跨裝置滾動與遮擋問題）。
- **SW 快取**：`my-space-cache-v1.0.9`。

## ⚙️ 程式碼撰寫規範

1. **模組化封裝**：所有事件監聽必須包在 `(function() { ... })();` 中。
2. **防重複綁定**：使用 `dataset.bound` 防止重複綁定。
3. **自訂彈窗**：禁止使用原生的 `alert()`、`confirm()`、`prompt()`。
4. **自訂彈窗**：所有確認動作請使用 `customConfirm(title, msg, okText, cancelText, isDanger)` 這個 Promise 函式。
5. **Toast 提示**：使用 `toast('訊息')` 顯示操作回饋。
6. **DOM 查詢**：使用 `const $ = (s) => document.querySelector(s)` 與 `$$`。
7. **資料儲存**：使用封裝好的 `LS` 物件（`LS.get`、`LS.set`）。
8. **圖片音效**：圖片與音效用 `IDB`（IndexedDB）。
9. **日期處理**：使用 `todayKey()` 取得 `YYYY-MM-DD`；使用 `dateKey(d)` 轉換 Date 物件。
10. **Google API**：使用 Google Identity Services (GIS) 進行登入。Token 暫存於 LocalStorage (`googleToken`, `googleTokenExp`)。
11. **多語系 (i18n)**：禁止在 HTML 中寫死任何介面文字。
12. **多語系 (i18n)**：所有文字必須加上 `data-i18n="key"`，placeholder 加上 `data-i18n-placeholder="key"`。
13. **多語系 (i18n)**：在 `lang.js` 中集中管理 `zh-TW`、`en` 與 `ja` 的翻譯。
14. **多語系 (i18n)**：`applyLanguage(lang)` 負責替換靜態文字，並**必須重新呼叫所有渲染函式**。
15. **多語系 (i18n)**：語言切換採輪替制（`zh-TW → en → ja`），按鈕文字動態顯示下一種語言。
16. **滾動鎖定**：`html, body` 永久 `overflow: hidden`。所有可滾動內容交由 `.scroll-box`（`overflow-y: auto`）處理，並加上 `padding-bottom: 120px` 避開 Footer。
17. **按鈕圖示化**：列表中的編輯與刪除按鈕，統一使用 `✎` 與 `×`，避免文字擠壓。

當我提出需求時，請依照以下步驟回覆：

1. **版本判定**：依上方「判定流程」告訴我這次更新屬於哪個級別。

4. **程式碼提供**：若改動較小，請用「🔍 找到這段程式碼… ✅ 替換為…」的方式。
5. **程式碼提供**：若改動較大、涉及架構或 HTML 結構，請直接提供**整份檔案的完整程式碼**。
6. **程式碼提供**：用註解標示 `// [NEW]` 方便我對照。
7. **排版規範**：所有提供的程式碼（包含 HTML, CSS, JS）請遵守「一個元素/屬性一行」的原則。
8. **文檔同步**：若有必要，請一併提供 `changelog.md` 或 `README.md` 的更新段落。
